# Cloudinary Setup & Direct Video Upload Architecture

This document describes the Cloudinary configuration, security constraints, and asynchronous transcoding lifecycle required for EduLanka Phase 3.

---

## 1. Security Architecture Overview

EduLanka uses signed, direct browser-to-Cloudinary uploads to protect media resources and prevent server bottlenecking:
1. **Authenticated Delivery (`type: 'authenticated'`)**: All instructional video assets are uploaded with `type: 'authenticated'`. Unauthenticated or hotlinked requests are rejected by Cloudinary's CDN. Access is only possible via short-lived, HMAC-signed URLs generated by EduLanka's API (`/media/manifest/:id` and `/media/playback/:id`).
2. **Quota Enforcement**: Before granting a signature token, `UploadService.getSignature()` queries `tenant_storage_usage` in PostgreSQL. If the school has exceeded its storage quota, upload signatures are blocked (`403 Forbidden`).
3. **Deterministic Signed Parameters**: Cloudinary requires that every parameter sent in the upload `FormData` (other than `file`, `cloud_name`, and `api_key`) matches the server's signed string. The backend signs:
   - `timestamp`
   - `folder`: `edulanka/<tenantId>/videos`
   - `allowed_formats`: `mp4,mov,avi,webm`
   - `type`: `authenticated`
   - `eager`: `sp_hd/m3u8`
   - `upload_preset` (if configured in environment)

## 2. Cloudinary Upload Preset Configuration

In the Cloudinary Management Console (`Settings -> Upload -> Upload presets`), configure an Upload Preset matching `CLOUDINARY_UPLOAD_PRESET`:

| Setting | Value | Rationale |
|---|---|---|
| **Preset Name** | e.g., `edulanka_video_preset` | Matches `CLOUDINARY_UPLOAD_PRESET` in `.env` |
| **Signing Mode** | **Signed** | Requires server-side HMAC-SHA1/SHA256 signature from `UploadService`. |
| **Delivery type** | **Authenticated** | Restricts video files from public CDN exposure. |
| **Allowed formats** | `mp4, mov, avi, webm` | Prevents non-video file uploads. |
| **Max file size** | `200 MB` (or tenant plan max) | Prevents denial-of-service via huge file payloads. |
| **Eager Transformations** | Streaming profile: `sp_hd/m3u8` | Generates adaptive bitrate HLS playlist (`.m3u8`) and `.ts` video segments asynchronously upon upload. |
| **Notification URL** | `https://<api_domain>/api/v1/upload/cloudinary-webhook` | Triggers async webhook notification when transcoding completes. |

## 3. Asynchronous Transcoding & "Ready Only When HLS Exists" Rule

Video playback in the EduLanka web portal and mobile app relies on HLS (`.m3u8`) for adaptive bitrate streaming across varying bandwidth in rural Sri Lanka.

1. **Immediate State**: When a video upload finishes in the browser, the frontend registers the asset via `POST /media` with `status: 'processing'`.
2. **Asynchronous Transcoding**: Cloudinary queues background jobs to generate HLS segments (`sp_hd/m3u8`).
3. **Webhook Arrival**: Once transcoding completes, Cloudinary dispatches a signed webhook payload to `/api/v1/upload/cloudinary-webhook`.
   - The webhook signature is verified using `CLOUDINARY_API_SECRET`.
   - The eager array is parsed for an entry with format `m3u8` or URL containing `.m3u8`.
   - **Status Transition**: The asset in `media_assets` transitions from `processing` to `ready` **ONLY** when `hls_url` is verified.
   - Storage consumption for both the master video and eager renditions is recorded in `tenant_storage_ledgers` (ADR-001).

## 4. Authenticated Offline MP4 Downloads (P3-S6)

For mobile offline learning:
1. Students request an offline download manifest via `GET /media/manifest/:id`.
2. The server verifies the student's enrollment and subscription, then generates an authenticated, short-lived signed MP4 URL:
   ```typescript
   signedMp4Url = cloudinary.url(asset.cloudinary_public_id, {
       resource_type: 'video',
       sign_url: true,
       type: 'authenticated',
       expires_at: expiresTimestamp,
       format: 'mp4',
   });
   ```
3. Cloudinary validates the signature and timestamp, delivering the MP4 directly to the mobile device for local AES-256-CTR encryption and offline caching.
